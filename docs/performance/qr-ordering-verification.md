# ผลตรวจ QR สั่งอาหาร รูปเมนู และสิทธิ์ · 23 ตุลาคม 2026

## ขอบเขต

ใช้โค้ดจริง FastAPI/React, PostgreSQL 16 แยก `khunflow_qr_test` ที่ loopback:55440, API พอร์ต 18043 และเว็บพอร์ต 5183 ไม่มีการเขียนข้อมูลร้านจริง บัญชี/รูปทดสอบสร้างเฉพาะฐานนี้ ภาพเมนูสีเขียวเป็น fixture ทดสอบ ไม่ใช่ภาพอาหารจริง

## ผล API: 44 ผ่าน / 0 ไม่ผ่าน

ผลดิบ: [qr-ordering-results.json](qr-ordering-results.json)

- Anonymous QR เมนู/สกุลเงินแยกร้าน ไม่ส่งต้นทุน สต็อก หรือพนักงาน
- ส่งคำขอ pending ไม่เพิ่มยอดขายและไม่หักสต็อก พนักงานรับแล้วหักตามสูตร แปลง 200 ml → 0.2 l
- การส่ง UUID ซ้ำพร้อมกันและการรับออเดอร์เดียวกันพร้อมกัน 3 ครั้งมีเพียงคำขอ/ยอดขายเดียว
- ออเดอร์แข่งกันใช้สต็อกชิ้นสุดท้ายรับได้เพียงออเดอร์เดียว ไม่ติดลบ สต็อกไม่พอ rollback และคง pending
- ปฏิเสธไม่เปลี่ยนสต็อก ยกเลิกคืนสต็อก คืนสถานะหักอีกครั้ง และลูกค้าเห็นสถานะที่เชื่อมกับออเดอร์จริง
- ข้ามร้าน, ลูกค้ายืนยันเอง, QR/receipt ผิด, ราคาดัดแปลง, สกุลเงินไม่ตรง, จำนวน/หมายเหตุเกิน ถูกปฏิเสธ
- ปิดโต๊ะหยุดคำขอ เปลี่ยน QR ทำให้ลิงก์เก่าใช้ไม่ได้ ลิงก์ติดตามเดิมยังใช้ได้
- รูปบันทึก/แปลง WebP, เมนูเผย URL ถูกต้อง, ไม่ไหลไปร้าน B, ข้ามร้านอัปโหลดไม่ได้
- ปฏิเสธ SVG ไฟล์เสีย และเกิน 5 MB โดยรูปก่อนหน้ายังอยู่ ลบรูปแล้วเมนูว่างและ URL เวอร์ชันเดิมคืน 404
- แคชเชียร์เริ่มต้นไม่มีสิทธิ์รูป เจ้าของให้สิทธิ์แล้วอัปโหลดได้โดยไม่ login ใหม่ แต่ยังแก้สินค้าไม่ได้ เพิกถอนแล้วถูกบล็อกทันที ผู้จัดการแก้สิทธิ์เองไม่ได้
- เปิด connection ใหม่ยังอ่านรูปจากฐานข้อมูลได้

## ตรวจผ่านเบราว์เซอร์

1. บันทึกภาพ QR ที่สร้างโดยหน้าโต๊ะจริง และถอดด้วย OpenCV ได้ลิงก์ `/table/{token}` ตรงกับโต๊ะ ไม่ใช้ URL ที่เขียนขึ้นมาทดแทน QR
2. ออกจากบัญชี เปิดลิงก์ที่ถอดได้ เลือกกาแฟ 2 รายการ ราคา 60 รวม 120 ใส่หมายเหตุ และส่งสำเร็จ
3. ระหว่าง pending ตรวจฐานข้อมูล สต็อกยังเท่าเดิมและจำนวนออเดอร์จริงไม่เพิ่ม รีเฟรชหน้ายังมีคำขอเดิม
4. เข้าบัญชีแคชเชียร์ กดรับใน POS ลูกค้าเห็น “ร้านรับออเดอร์แล้ว” และมีเลขออเดอร์/ชื่อโต๊ะ/หมายเหตุในประวัติ

| จุดตรวจจาก browser flow | สต็อก A | สต็อก B | จำนวน Order |
|---|---:|---:|---:|
| ก่อนลูกค้าส่ง | 5 l | 5 l | 3 |
| ส่งแล้ว pending #9 | 5 l | 5 l | 3 |
| แคชเชียร์รับ → Order #4 | 4.8 l | 5 l | 4 |

5. อัปโหลดผ่าน file chooser และปุ่มบันทึกจริงของหน้า **รูปเมนู** สำเร็จ รูปใหม่ปรากฏในหน้าลูกค้าและ `naturalWidth > 0`
6. เจ้าของเปิดสิทธิ์รูปแคชเชียร์ร้าน A ผ่าน UI แล้วบันทึก/รีเฟรชยังเป็น true สลับ B ยังเป็น false และ B ไม่มีรูปของ A
7. แม้บัญชีพนักงานเลือก B (USD) หน้า QR ลูกค้ายังเป็นร้าน A, THB และรูปของ A
8. ตรวจ viewport 390×844 เนื้อหาจริง 375px รวม scrollbar ไม่มี horizontal overflow รูปโหลดครบ และคืน viewport ตามเดิม
9. Restart PostgreSQL ทดสอบ และเปิด API ด้วย startup/migration จริง (`app.main`) ผ่าน รูปเวอร์ชันเดิมยังคืน 200 พร้อม bytes เดิม และเมนู/โต๊ะยังอยู่
10. ดาวน์โหลด QR พร้อมโลโก้จากลิงก์จริง ได้ PNG 640×820 และถอดรหัสกลับเป็นโต๊ะ B ได้ตรง ปรับการดาวน์โหลดให้เตรียมภาพล่วงหน้าและใช้ลิงก์ดาวน์โหลดตรง เพื่อไม่ติดรอโหลดฟอนต์ระหว่างคลิก

## วิธีตรวจซ้ำ

ติดตั้ง `backend/tests/requirements-qr.txt` ใน venv และสร้าง PostgreSQL ทิ้งได้เท่านั้น:

```powershell
docker run -d --name khunflow-qr-check-pg --label codex.task=khunflow-qr-check -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=qr_test_only -e POSTGRES_DB=khunflow_qr_test -p 127.0.0.1:55440:5432 postgres:16-alpine
.venv/Scripts/python.exe -u backend/tests/test_table_ordering.py
```

Harness ตรวจ driver/host/port/ชื่อฐานก่อนเชื่อม ไม่รับ URL ฐานจริง รันทดสอบข้อมูลเดิมซ้ำได้ แต่เลขคำขอ/ออเดอร์ในภาพเป็นรอบบันทึกหลักฐานนี้

## ข้อจำกัด

ถอดภาพ QR และเปิดผ่านเบราว์เซอร์ ไม่ได้ใช้กล้องสมาร์ตโฟนจริง ไม่ทดสอบโหลดพร้อมกันจำนวนมากหรือสภาพ Wi-Fi ร้านจริง การตรวจ deploy เป็นการอ่าน revision/ไฟล์บน Vercel และ Render แยกจาก flow เขียนข้อมูลบนฐานทดสอบ
