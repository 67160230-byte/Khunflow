# ทดสอบลบและกู้คืนโต๊ะบนเว็บจริง

ทดสอบผ่านเบราว์เซอร์ที่ `https://khunflow.vercel.app/` ช่วงคืนวันที่ 23–24 ตุลาคม 2026 (Asia/Bangkok) ตามคำขอให้ใช้โต๊ะทดสอบบนระบบจริง

## ผลที่ตรวจเห็นจริง

| ขั้นตอน | ผล |
| --- | --- |
| สร้างโต๊ะ `ทดสอบลบกู้คืน 23ตค69` | จำนวนโต๊ะเพิ่มจาก 11 เป็น 12 และเปิดหน้าเมนูผ่านลิงก์ QR ได้ |
| ส่งคำขอ #2 เมนูชาเขียว | ส่งได้ แต่รับไม่ได้เพราะผงชาเขียวไม่พอ จึงปฏิเสธพร้อมเหตุผลว่าเป็นคำขอทดสอบ |
| สร้างเมนูทดสอบราคา 1 บาท ไม่ผูกสูตรวัตถุดิบ | ส่งคำขอ #3 และรับสำเร็จเป็นออเดอร์ #3 มีชื่อโต๊ะ หมายเหตุ รายการและยอดครบในประวัติ POS |
| กดลบโต๊ะและยืนยัน | โต๊ะหายจากรายการใช้งาน จำนวนเหลือ 11 และปรากฏใน `โต๊ะที่ลบ (1)` |
| เปิด QR เก่าหลังลบ | แสดง `เปิดเมนูไม่ได้` และ `QR ไม่ถูกต้องหรือโต๊ะนี้ปิดรับออเดอร์ กรุณาติดต่อพนักงาน` ไม่แสดงปุ่มเลือกเมนู |
| เปิดประวัติ POS หลังลบ | ข้อความทั้งแถวของออเดอร์ #3 ตรงกับก่อนลบ รวมชื่อโต๊ะ หมายเหตุ ยอด 1 บาท และสถานะสำเร็จ |
| ใบติดตามลูกค้าหลังลบ | ยังคงอ่านคำขอ #3 และออเดอร์ #3 สถานะร้านรับออเดอร์แล้วได้ แม้ QR เดิมโหลดเมนูไม่ได้ |
| กดกู้คืนโต๊ะ | จำนวนกลับเป็น 12, ถังลบเหลือ 0, โต๊ะคืนมาโดยปิดรับออเดอร์และเปลี่ยน QR |
| เปิดรับออเดอร์บนโต๊ะที่กู้คืน | QR ใหม่เปิดเมนูได้จริง ส่วนการลอง QR เก่าซ้ำยังเปิดเมนูไม่ได้ |
| เปิดประวัติหลังกู้คืนและรีเฟรช | ข้อความทั้งแถวออเดอร์ #3 ยังตรงกับก่อนลบ การกู้คืนและปิดโต๊ะยังคงอยู่หลังรีเฟรช |

## สถานะหลังเก็บงาน

- ยกเลิกออเดอร์ทดสอบ #3 พร้อมเหตุผล `เสร็จสิ้นการทดสอบลบ/กู้คืนโต๊ะบนเว็บจริง ไม่ใช่ยอดขายจริง` ตรวจว่าแสดง `ยกเลิกแล้ว` และใบติดตามลูกค้าเปลี่ยนตาม
- เมนู `ทดสอบระบบโต๊ะ 23ตค69 ไม่ขายจริง` ถูกหยุดขายแล้ว แสดง `ปิดใช้งาน` และปุ่ม `นำกลับมาขาย`
- คงโต๊ะทดสอบที่กู้คืนไว้ให้ตรวจดู แต่ปิดรับออเดอร์แล้ว จำนวนรวม 12 โต๊ะ เปิดรับ 11 โต๊ะ / 38 ที่นั่งตามเดิม
- ไม่รับ ปฏิเสธ หรือลบคำขอของโต๊ะอื่น ไม่เปลี่ยนสูตรหรือเติมสต็อกจริงเพื่อให้ทดสอบผ่าน เมนู 1 บาทไม่มีสูตร จึงไม่ใช้วัตถุดิบ

## ขอบเขต

เป็นการกด UI และอ่านผลจากระบบจริง ไม่ใช่ชุด API SQLite ก่อนหน้า การเปิด QR ใช้ลิงก์บนการ์ดแทนกล้องโทรศัพท์ ไม่ได้ทดสอบส่งจากตะกร้าเก่าค้างไว้หลังลบ และไม่ได้ทดสอบการลบ/กู้คืนพร้อมกันหลายคน

พบประเด็น UX เพิ่มเติม: ข้อความผิดพลาด `ผงชาเขียวมีไม่พอ` ใน POS หายเมื่อรอบโหลดรายการรอยืนยันทำงาน ทำให้ผู้ใช้ที่อ่านไม่ทันอาจคิดว่าปุ่มรับออเดอร์ไม่ทำงาน ประเด็นนี้ยังไม่ได้แก้ในงานตรวจครั้งนี้
